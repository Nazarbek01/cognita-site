# Cognita — AI-навигатор карьеры для студентов и профессионалов

Настоящий сайт, не прототип: тест из 30 утверждений → топ-5 профессий из 114 (21 сфера) с объяснением «почему подходит» → пробелы в навыках → персональный роадмап. Два пути: «Я студент» и «Я профессионал». ИИ — OpenAI API, база для сохранённых результатов — Notion, хостинг — Netlify.

> Язык сайта — английский (B2), как в задании. Эта инструкция — на русском, для команды.

---

## 1. Что работает, а что честно помечено «Скоро»

| Функция | Статус на сайте |
|---|---|
| 01 AI Career Assessment (тест + топ-5 + «почему») | **Работает** |
| Путь «Я профессионал» (сфера, стаж, образование, цель) | **Работает** |
| Каталог 114 профессий с поиском и фильтром по 21 сфере | **Работает** |
| 03 Skill-Gap Analysis (каких навыков не хватает) | **Работает** |
| 04 Personal Roadmap (шаги, отметки «готово») | **Работает** |
| 02 Market Analytics (зарплаты, спрос) | **Скоро.** Цифр на сайте нет специально: показываем число только с источником и датой |
| 05 Quests & Rewards | **Скоро** |
| 06 Weakness Analytics | **Скоро** |

Ничего не выдумано: в каталоге профессий нет ни зарплат, ни статистики спроса. Вопросы теста написаны командой — это **не** валидированный психологический тест, и сайт так и говорит. Насколько каждая из шести областей интересов важна для профессии — **оценка команды** по типам Холланда (RIASEC), не официальные данные; это написано на сайте.

## 2. Как устроен сайт (коротко)

```
public/                  ← сам сайт (HTML + CSS + JS, без сборки и без фреймворка)
  index.html
  assets/css/            tokens.css (все цвета/радиусы/тени/шрифты) → site.css
  assets/js/             app.js (роутер, логика) · views.js (экраны) · api.js · store.js
  assets/img/3d/         150 3D-картинок (Microsoft Fluent Emoji, лицензия MIT, файл LICENSE.txt рядом)
  assets/img/brand/      логотип команды (знак и надпись) с прозрачным фоном
  shared/                движок подбора и каталог — один и тот же код работает и в браузере, и на сервере
tools/                   fetch_images.py + images.mjs — заново скачать 3D-картинки, если поменяли каталог
netlify/functions/       4 серверные функции: match, result, feedback, health
netlify/lib/             OpenAI, Notion, защита (лимиты, проверка источника)
test/                    25 автотестов движка и сервера (без сети, на подделках OpenAI/Notion)
e2e/run.mjs              тест в настоящем браузере: все экраны, телефон и компьютер
dev-server.mjs           локальный просмотр
netlify.toml             настройки Netlify + заголовки безопасности
```

**Как считается совпадение (прозрачная формула, показана на сайте в «How is this match calculated?»):**
- Студент: 70 % интересы + 20 % навыки (из базовых, которые он отметил) + 10 % любимые школьные предметы.
- Профессионал: 60 % интересы + 30 % навыки (все навыки профессии) + 10 % цель (расти в своей сфере или сменить её).
- «Интересы» внутри: 65 % — **форма профиля** (совпадает ли, какие области у человека выше других, с тем, что важнее всего для профессии; корреляция) и 35 % — уровень баллов в этих областях. Поэтому даже при низких баллах получается осмысленный порядок.
- В топ-5 не больше **2 профессий из одной сферы**, чтобы были реальные варианты.
- Если все шесть баллов почти одинаковые (например, один и тот же ответ на всё), сайт **предупреждает** перед подсчётом и показывает пометку на результатах. Ничьи между профессиями решаются не порядком в списке (раньше из-за этого всегда первым был Data Analyst), а стабильной «жеребьёвкой».

ИИ получает 15 лучших кандидатов, выбирает 5, пишет объяснение и может сдвинуть процент **не больше чем на 15 пунктов** от расчёта. Сервер проверяет ответ ИИ: профессии не из списка кандидатов выбрасываются, больше 2 из одной сферы не пропускаются, навыки берутся только из реального списка. Если ИИ не ответил, ответил мусором, ключа нет или он выключен — сайт сам считает по правилам и честно пишет «Calculated by rules».

**Приватность:** нет аккаунтов и паролей; имя, почта и дата рождения не спрашиваются. Необязательное имя живёт только в браузере. Заметка для ИИ очищается от e-mail и телефонов и **не сохраняется** в Notion. Сохранённый результат открывается по случайному коду `COG-XXXX-XXXX-XXXX` (≈59 бит) — у кого код, тот видит результат.

## 3. Посмотреть у себя на компьютере (без ключей)

Нужен только Node.js 20+ (`node -v`).

```bash
node dev-server.mjs --mock
# открыть http://localhost:8888
```

Режим `--mock` — **подделки** OpenAI и Notion в памяти. Тексты «ИИ» там заготовленные, по ним качество ИИ оценивать нельзя. Нужен, чтобы пройтись по экранам.

Тесты:

```bash
npm test          # 25 тестов движка и сервера
npm run e2e       # браузерный тест, 275 проверок (нужен Playwright + Chromium)
```

## 4. Запуск в интернете (Netlify) — по шагам

Всё это можно сделать только под вашими аккаунтами — ключи нельзя выдавать никому, в том числе мне.

### Шаг 1. Notion: интеграция и токен

База уже создана в вашем Notion: страница **«Cognita: данные сайта»** с двумя базами (результаты и отзывы). Дневник не затронут.

1. Откройте <https://www.notion.so/profile/integrations> → **New integration** (тип *Internal*), назовите «Cognita site».
2. Скопируйте **Internal Integration Secret** — это `NOTION_TOKEN`.
3. Откройте страницу **«Cognita: данные сайта»** → **…** → **Connections** → добавьте «Cognita site». Без этого шага сайт получит ошибку доступа.

ID баз уже прописаны в `.env.example` (`NOTION_RESULTS_DB`, `NOTION_FEEDBACK_DB`).

### Шаг 2. OpenAI: ключ

1. <https://platform.openai.com> → **API keys** → создать ключ → это `OPENAI_API_KEY`.
2. Подписка ChatGPT **не включает** API: нужен отдельный баланс в разделе Billing.
3. **Обязательно** поставьте месячный лимит расходов (Billing → Limits). Это настоящая защита бюджета; встроенный лимит запросов на сайте работает «по возможности» (память функции сбрасывается).
4. Модель по умолчанию — `gpt-6-luna`. Если в вашем аккаунте она называется иначе или недоступна, задайте переменную `OPENAI_MODEL`. Если ИИ недоступен, сайт всё равно работает по правилам.

### Шаг 3. GitHub

Создайте пустой репозиторий (лучше **Private**) и загрузите в него содержимое этой папки. Файл `.env` в репозиторий не попадает (он в `.gitignore`).

### Шаг 4. Netlify

1. <https://app.netlify.com> → **Add new site → Import an existing project** → GitHub → ваш репозиторий.
2. Настройки сборки подтянутся из `netlify.toml` (`publish = public`, функции в `netlify/functions`). Build command — пусто.
3. **Site configuration → Environment variables**, добавьте:

| Переменная | Значение |
|---|---|
| `OPENAI_API_KEY` | ключ OpenAI |
| `NOTION_TOKEN` | токен интеграции |
| `NOTION_RESULTS_DB` | `c0d61905265f470b9f57b7ce4f31b403` |
| `NOTION_FEEDBACK_DB` | `a1a1062da96c4e9fb938d6c0d465a60f` |
| `OPENAI_MODEL` | *(необязательно)* |
| `ADMIN_TOKEN` | *(необязательно)* любая длинная случайная строка — нужна для глубокой проверки |

4. **Deploys → Trigger deploy** (после добавления переменных нужен новый деплой).

> Перетаскивание папки (drag-and-drop) — не рекомендуется: для функций и переменных надёжнее импорт из Git.

### Шаг 5. Проверка

Откройте `https://ВАШ-САЙТ.netlify.app/api/health` — должно быть `{"ok":true,"openai":true,"notion":true,...}`. `false` значит, что переменная не задана.

Глубокая проверка настоящих подключений (нужен `ADMIN_TOKEN`):

```bash
curl -H "x-admin-token: ВАШ_ТОКЕН" "https://ВАШ-САЙТ.netlify.app/api/health?deep=1"
```

Затем пройдите тест сами и посмотрите, что в Notion появилась строка в базе результатов.

## 5. Перед тем как давать ссылку людям

1. **Контакт для удаления данных.** В `public/assets/js/site.config.js` впишите настоящий адрес в `contactEmail`. Пока он пуст, в Privacy Notice написано, что адрес будет опубликован до запуска — я не придумываю чужих контактов.
2. **Несовершеннолетние.** Аудитория — 15–22 года. Имя, почта и дата рождения не собираются, но ответы теста + код — это данные о человеке. Уточните у преподавателя, какое согласие нужно для школьников, и при необходимости дополните Privacy Notice.
3. **Что видно в Notion.** Там лежат ответы теста, баллы, профессии и код. Не давайте доступ к странице посторонним.
4. **Удаление по запросу.** Человек присылает код → вы находите строку в Notion и удаляете.

## 6. Как менять содержимое

- Профессии, сферы, их навыки и веса — `public/shared/careers.mjs` и `skills.mjs`. Поменяли каталог — увеличьте `CATALOGUE_VERSION` в `config.mjs` и запустите `npm test` (тесты проверяют целостность, картинки и отсутствие «выдуманных цифр»).
- Новая профессия с новой картинкой: впишите в поле `img` имя эмодзи из Fluent (например `woman-pilot`) и запустите `python3 tools/fetch_images.py <список файлов репозитория fluentui-emoji>` (как получить список — написано в начале скрипта).
- Вопросы — `public/shared/questions.mjs` (ровно 30, по 5 на область).
- Цвета, радиусы, тени, шрифты — **только** `public/assets/css/tokens.css`. Три слоя: primitive → semantic → component. Голых hex-цветов в остальном CSS и JS нет. Палитра: молочный фон, розовый, синий, голубой (из логотипа). Заголовки — шрифт Unbounded (лицензия OFL, файл рядом со шрифтами), текст — Inter.

## 7. Честные ограничения

- Живой вызов OpenAI и Notion я проверить не мог (нет ваших ключей): логика покрыта тестами на подделках (успех, мусор, ошибка 500, таймаут, отказ, нет ключа, Notion недоступен). Первый настоящий прогон — ваш шаг 5.
- Названия модели `gpt-6-luna` я взял из документации OpenAI; при расхождении используйте `OPENAI_MODEL`.
- Лимит запросов хранится в памяти функции — это не жёсткая защита. Настоящая — лимит расходов в OpenAI.
- Market Analytics, Quests & Rewards, Weakness Analytics — пока только заглушки с пометкой «Coming soon».
- Веса интересов для 114 профессий — оценка команды по типам Холланда, а не данные O*NET один в один. Описания профессий — общие, без цифр и без привязки к конкретным вузам.
- Настоящих фотографий на сайте нет: стоковые сайты недоступны из среды, где сайт собирался. Картинки — 3D-эмодзи Microsoft (MIT). Свои фото команды можно добавить позже.
